## OpenFOAM Status

OpenFOAM is partially integrated:

* Runtime detection exists.
* The UI shows OpenFOAM status in Run Monitor.
* The app can detect commands such as `openfoam`, `simpleFoam`, `blockMesh`, and `surfaceFeatureExtract`.

Not yet implemented:

* real OpenFOAM case generation
* running `blockMesh`, meshing, solver, or post-processing commands
* parsing real OpenFOAM logs
* parsing real OpenFOAM result files
* writing real exports to disk

## Results Visualization Decision

Live run feedback should use traditional engineering views that are more informative during solving:

* residual plots
* force, drag, lift, and coefficient charts when available
* solver warnings and summarized logs
* stage progress, timing, and mesh/post-processing status

These graphs belong on the Run Monitor page. After a run completes, graph views should remain available and be exportable/saveable, preferably as `SVG`, with `PNG` and `TIFF`/`TIF` as practical raster alternatives.

Animated flow visualization should be a post-completion replay built from saved result intervals. For steady-state cases, replay should be labeled as iteration/convergence replay rather than physical-time animation.

## Orientation UX Decision

The Project page object viewer should show the incoming flow direction after a STEP/STP file is loaded, so the user can orient the body deliberately before simulation setup.

## Source Install Flow Added Today

Implemented locally:

* `POST /api/openfoam/install`
* requires explicit permission header:
  * `X-Tarangini-Install: openfoam-source`
* UI button:
  * **Install OpenFOAM Source**
* browser confirmation before install request
* source checkout target:
  * `.tarangini/openfoam/`
* `.tarangini/` added to `.gitignore`
* clones or updates official OpenFOAM Foundation source repos:
  * `https://github.com/OpenFOAM/OpenFOAM-13.git`
  * `https://github.com/OpenFOAM/ThirdParty-13.git`
* writes:
  * `.tarangini/openfoam/activate-openfoam.sh`

Important: this prepares source repositories only. It does not compile OpenFOAM or install OS dependencies yet.

## Windows/OpenFOAM Decision

For Windows, the likely correct product path is not native Windows OpenFOAM installation. The practical validated path should be:

1. detect Windows
2. detect WSL2
3. detect Ubuntu distro
4. ask user permission to install/enable WSL2 and Ubuntu if missing
5. install validated OpenFOAM inside Ubuntu/WSL2
6. execute OpenFOAM through `wsl.exe`
7. store WSL distro, OpenFOAM version, and paths in provenance

Installation policy:

* OpenFOAM, WSL2, Ubuntu, and related runtime dependencies must only be installed after explicit user permission at install time.
* If the user declines installation, Tarangini should keep setup/model preview available and block simulation execution with clear next steps.

Source install can remain useful, but WSL2 package/runtime integration should be prioritized for Windows.

Relevant docs:

* OpenFOAM Foundation Windows install: `https://openfoam.org/download/windows/`
* Microsoft WSL install docs: `https://learn.microsoft.com/en-us/windows/wsl/install`
